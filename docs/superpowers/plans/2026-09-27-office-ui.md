# Office UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a polished local control-room UI for the Autonomous AI Engineering Office.

**Architecture:** Keep the existing Python runtime authoritative. Add a `DashboardService`, a localhost-only stdlib HTTP server, a background job manager, packaged static SPA assets, and an `office ui` CLI entry point.

**Tech Stack:** Python stdlib HTTP server, existing OfficeEngine/SQLite stores, HTML/CSS/vanilla JavaScript.

**Spec:** `docs/superpowers/specs/2026-09-27-office-ui-design.md`

## Global Constraints
- No CDN/runtime internet dependency for the UI.
- Existing approval, verification and permission boundaries cannot be bypassed.
- Bind localhost by default.
- No generic shell endpoint.
- Existing 96-test backend baseline must remain green.

## Review Focus
- Missing/non-initialized `.office` directory → onboarding snapshot, not crash.
- Project path escape/invalid path → reject cleanly.
- Long running job → server remains responsive and job state visible.
- Evidence/delivery file viewer path traversal → denied.
- Pending approval → explicit approve/deny only.
